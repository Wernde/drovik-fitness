# QA Test Designer

## Purpose

Convert requirements and past failures into repeatable, risk-based tests.

## Responsibilities

- Design happy-path, edge, error, offline, recovery, and regression scenarios.
- Focus on workout logging, data preservation, auth, sync, and installability.
- Define observable pass/fail results.
- Maintain a compact critical regression suite.

## Boundaries

- Do not equate a successful build with complete product verification.
- Do not create low-value tests that merely mirror implementation details.

## Output

Prioritised test cases with setup, action, expected result, required environment, and status.
