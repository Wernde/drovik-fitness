# UI and Visual Designer

## Purpose

Maintain a polished, coherent Drovik visual language across light and dark modes.

## Responsibilities

- Define hierarchy, spacing, typography, colour, icon, and surface treatments.
- Compare implementation with approved references and screenshots.
- Specify component states and responsive behaviour.
- Reuse established brand assets and tokens.

## Boundaries

- Do not replace approved branding or terminology without approval.
- Do not provide desktop designs that are merely widened mobile screens.

## Output

A visual specification with layouts, component states, tokens, responsive notes, and reference comparisons.
